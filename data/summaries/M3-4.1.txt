## เรื่องที่ออกบ่อย
| เรื่อง | ประเด็นที่ต้องจำ |
| ปัจจัยที่ทำให้เทคโนโลยีเปลี่ยน | **ความก้าวหน้าของวิทยาศาสตร์/ศาสตร์อื่น** · ความต้องการ/ปัญหา · ต้นทุน · สิ่งแวดล้อม · กฎระเบียบสังคม |
| แอนะล็อก → ดิจิทัล | ดิจิทัล **ทนต่อ** สัญญาณรบกวน กู้คืนได้ → เสถียร คมชัด แม่นยำ (ไม่ได้ทำให้รบกวนเกิดน้อยลง) |
| กระบวนการออกแบบ | ระบุปัญหา → รวบรวมข้อมูล → เลือกแนวทาง → ออกแบบ/วางแผน → สร้าง → **ทดสอบ ประเมิน** → ปรับปรุง → นำเสนอ |
| ภาพร่างและขั้นตอนสร้าง | ทำให้แผนชัด ประหยัดเวลา/วัสดุ ลดความผิดพลาด (ข้อมูลเริ่มต้นมาจากการรวบรวมข้อมูล **ก่อนหน้า**) |
| แนวคิดลีน | ตัดของเปล่าประโยชน์ **โดยทรัพยากรเท่าเดิม** · ลดขั้นตอน ลดการรอ จัดของให้หยิบง่าย · ไม่ใช่เพิ่มคนหรือซื้อเพิ่ม |
| ทดสอบประสิทธิภาพ | ทดสอบในสภาพ **ใช้งานจริง** ตามเกณฑ์ (ลอยน้ำ ทนทาน) แล้วนำผลมาปรับ |
| เริ่มพัฒนางานให้ผู้ใช้ | เริ่มจาก **สิ่งที่ผู้ใช้ติดขัดและอยากได้** ก่อน แล้วค้นหา ออกแบบ ทดสอบกับผู้ใช้ |
| เลือกทางเลือก | ตรวจ **เงื่อนไข** (งบ ผลกระทบต่อการใช้งานเดิม แก้ตรงจุด) แล้ววางแผนทีละขั้น |
| ทรัพย์สินทางปัญญา | ลิขสิทธิ์ · สิทธิบัตร · เครื่องหมายการค้า ต้องไม่ละเมิด |
!! ลำดับกระบวนการ: **ข้อมูล → เลือก → ออกแบบ → สร้าง → ทดสอบ** · ทดสอบอยู่ **หลังสร้าง** · การร่างวิธีและสืบค้นอยู่ **ก่อน** ทดสอบ
!! "ลีน" = **ได้งานเท่าเดิมหรือดีกว่าด้วยทรัพยากรเท่าเดิม** (เพิ่มคน เพิ่มงบ ไม่ใช่ลีน)
## ข้อสอบชอบถาม (พลาดบ่อย)
?? โจทย์เรียงขั้นตอนโครงงาน: หา **ขั้นหาข้อมูล** (ต้นสุด) แล้ว **เลือก/ออกแบบ → ติดตั้ง/สร้าง → ทดสอบ** (ท้ายสุด)
?? โจทย์ถามเหตุที่เทคโนโลยีเปลี่ยนมากสุด: เลือก **ความรู้วิทยาศาสตร์และศาสตร์อื่นที่ก้าวหน้า** เมื่อเป็นเรื่องวัสดุ/วิธีใหม่
?? โจทย์ให้เงื่อนไข (งบจำกัด ห้ามกระทบงาน): ตัดตัวเลือกที่ **เกินงบ** หรือ **รบกวนงานเดิม** เหลือวิธีที่ปรับทีละขั้น

## ปัจจัยที่ทำให้เทคโนโลยีเปลี่ยนแปลง
[[fig:m3-tech-change|ปัจจัยที่ผลักดันการเปลี่ยนแปลงของเทคโนโลยี]]
• **เทคโนโลยี** = การนำความรู้ (วิทยาศาสตร์ คณิตศาสตร์ ศาสตร์อื่น) มาแก้ปัญหา/พัฒนาสิ่งของวิธีการ
• ปัจจัยที่ทำให้เปลี่ยน: **ความก้าวหน้าทางวิทยาศาสตร์และศาสตร์อื่น** (วัสดุใหม่ นาโนเทคโนโลยี) · **ความต้องการ/ปัญหา** (โรคระบาด ขยะ) · **ต้นทุน** · **สิ่งแวดล้อม** · **กฎระเบียบ/สังคม**
ex: ฟิล์มกันน้ำสำหรับโทรศัพท์ผลิตจากวัสดุผิวแบบใหม่ที่ผลักน้ำ → สาเหตุที่ทำให้เทคโนโลยีเปลี่ยนมากที่สุดคือ **วิทยาศาสตร์ (วัสดุ) ที่ก้าวหน้า** (ไม่ใช่เพียงลดต้นทุนหรือกฎหมาย)
ex: รถไฟฟ้าแพร่หลายเพราะกฎควบคุมไอเสียเข้มงวด และแบตเตอรี่ราคาลง → ปัจจัยคือ สิ่งแวดล้อม + ต้นทุน + ความก้าวหน้าของวิทยาศาสตร์
?? โจทย์ "สาเหตุที่ทำให้เทคโนโลยีเปลี่ยนมากที่สุด": ถ้าเรื่องคือ **วัสดุใหม่ วิธีผลิตใหม่ที่เกิดจากความรู้** ตอบ **ความก้าวหน้าของวิทยาศาสตร์/ศาสตร์ต่าง ๆ**
## แอนะล็อกและดิจิทัล
[[fig:m3-analog-digital|เปรียบเทียบสัญญาณแอนะล็อกกับดิจิทัล]]
• **แอนะล็อก**: ต่อเนื่อง · มีสัญญาณรบกวน → **ค่าเปลี่ยน** คุณภาพลดทันที
• **ดิจิทัล**: ใช้ 2 ค่า (0 กับ 1) · มีสัญญาณรบกวน → **กู้คืนค่าเดิมได้** → ทน รบกวนได้ดี
• เหตุผลที่พัฒนาไปเป็นดิจิทัล: **เสถียร** · **คุณภาพคมชัด** · **แม่นยำ**
ex: ถ้าโจทย์ให้ข้อความว่า ดิจิทัลทนต่อสัญญาณรบกวน คุณภาพคมชัด ความแม่นยำสูง → "ต้องการให้สัญญาณรบกวนเกิดน้อยลง" **ไม่ใช่** เหตุผลที่โจทย์ระบุ (ดิจิทัลแค่ทนต่อได้)
?? โจทย์ "ข้อใดไม่ใช่สาเหตุ" ที่ข้อความให้มา: ตัดสาเหตุที่ **ไม่อยู่ในข้อความ** (เช่น ลดการเกิดสัญญาณรบกวน)

## ลำดับขั้นของงานออกแบบแบบวิศวกร
[[fig:m3-eng-process|กระบวนการออกแบบเชิงวิศวกรรม]]
| ขั้น | ทำอะไร | ตัวอย่างโครงงานฟาร์มผัก |
| ระบุปัญหา | ผักตายเพราะลืมให้น้ำ | ต้องการระบบให้น้ำอัตโนมัติ |
| รวบรวมข้อมูล | ค้นหาข้อมูล เทียบอุปกรณ์ ราคา | หาราคาปั๊ม ท่อ ตัวตั้งเวลา |
| เลือกแนวทาง | เปรียบเทียบ ตัดสินใจ | เลือกตัวตั้งเวลาแบบประหยัดและทนน้ำ |
| ออกแบบ วางแผน | ภาพร่าง ขั้นตอน | วาดผังท่อ กำหนดเวลา |
| สร้าง ติดตั้ง | ลงมือทำ | ติดตั้งอุปกรณ์ |
| ทดสอบ ประเมิน | ทดสอบใช้งานจริง | ตั้งเวลา เปิด-ปิด ตรวจรั่ว |
| ปรับปรุง นำเสนอ | แก้ข้อบกพร่อง สรุปผล | เปลี่ยนข้อต่อที่รั่ว |
ex: โครงงานระบบป้องกันนกกินข้าวในสวนผลไม้ มี 5 ขั้น: (ก) ติดตั้งสายล่อและเครื่องทำเสียง (ข) เทียบข้อมูลและเลือกอุปกรณ์ (ค) หาข้อมูลชนิดและราคาอุปกรณ์ (ง) ทดสอบว่านกลดลงหรือไม่ (จ) ออกแบบตำแหน่งและจำนวนอุปกรณ์ → ลำดับ **ค → ข → จ → ก → ง**
ex: ถ้าขั้น "ทดสอบ" เจอว่าเครื่องทำเสียงทำให้ชาวบ้านรำคาญ → กลับไป **ปรับปรุง** (เปลี่ยนเวลา/เสียง) แล้วทดสอบใหม่
## ภาพร่างและแผนขั้นตอนช่วยอะไรในงานต่อไป
• ภาพร่างและขั้นตอนเป็นผลของขั้น **ออกแบบ** ทำให้ **ทำงานตามแผนได้ · ใช้เวลาและวัสดุน้อยลง · พลาดตอนสร้างน้อยลง**
• **ข้อมูลที่ใช้ตัดสินใจเลือก** ได้มาจากขั้น **รวบรวมข้อมูล** (ก่อนออกแบบ) ไม่ใช่ประโยชน์ของภาพร่าง
ex: ทีมทำที่เก็บรองเท้าจากไม้ เขียนภาพร่างพร้อมขนาดและขั้นตอนตัดต่อ → ประโยชน์: รู้ขนาดไม้ที่ต้องซื้อ (ประหยัดวัสดุ) · ลดการตัดผิด · แบ่งงานได้ · แต่ข้อมูลว่า "ไม้ชนิดไหนทนที่สุด" มาจากการรวบรวมข้อมูล
?? โจทย์ "ข้อใดไม่ใช่ผลดีของภาพร่างกับแผน": ตัดตัวเลือกที่ **มาก่อนการออกแบบ** (ข้อมูลที่นำไปสู่การออกแบบ)
?? โจทย์เรียงลำดับตามกระบวนการออกแบบ: ขั้นหาข้อมูล → ขั้นเปรียบเทียบเลือก → ขั้นออกแบบ → ขั้นติดตั้ง → ขั้นทดสอบ
@@ M3 | ว 4.1 | ม.2/3 | ออกแบบวิธีภายใต้เงื่อนไขและทรัพยากร (ออก 1 ข้อ)
## แนวคิดแบบลีน: ลดความสูญเปล่า
• **ลีน** = กำจัดสิ่งที่เปล่าประโยชน์ (การรอ ขั้นตอนซ้ำ เดินวนไปมา ของวางไม่เป็นระเบียบ) โดย **ไม่เพิ่มทรัพยากร**
• วิธีแบบลีน: **ลดขั้นตอน** · **จัดลำดับงาน/คิว** · **จัดวางของให้หยิบง่าย** · แบ่งหน้าที่ชัดเจน
• ไม่ใช่ลีน: **เพิ่มพนักงาน เพิ่มเครื่องมือ เพิ่มงบ** (เป็นการเพิ่มทรัพยากร)
ex: ร้านกาแฟคนมาก รอนาน พนักงานคนเดียวทำทุกอย่าง วางอุปกรณ์กระจัดกระจาย → แนวทางลีน: จัดอุปกรณ์ให้อยู่ใกล้มือ · แยกจุดรับออเดอร์กับจุดชง · ทำป้ายคิว · ไม่ใช่ "เพิ่มพนักงานอีก 3 คน"
?? โจทย์ "ข้อใดไม่สอดคล้องกับลีน": ตอบ **เพิ่มจำนวนคน/เพิ่มอุปกรณ์/เพิ่มงบ**

## การทดสอบประสิทธิภาพในสภาพใช้งานจริง
• ทดสอบ **ตามเกณฑ์ที่ต้องการ** ใน **สภาพที่จะใช้งานจริง** (ลอยน้ำ ทนแดด ทนฝน) เป็นเวลาพอสมควร
• เทียบผลของแต่ละวัสดุ/แบบ แล้ว **นำผลมาปรับปรุง**
• การ **สืบค้นข้อมูล** หรือ **ร่างวิธีประกอบ** เป็นขั้นตอนก่อนหน้า ไม่ใช่การทดสอบ
• **ความสวยงาม** ไม่ใช่เกณฑ์ ถ้าโจทย์ต้องการความแข็งแรง/การลอย
ex: ชุมชนอยากได้ที่คลุมแปลงผักกันฝนจากวัสดุเหลือใช้ นักเรียนทดสอบโดยนำแต่ละแบบไปตั้งกลางแจ้ง 2 สัปดาห์ ดูการรั่วซึมและการพัง แล้วเลือกแบบที่ดีที่สุด → **ทดสอบในสภาพใช้งานจริง** ✓ · การเปิดดูรูปจากอินเทอร์เน็ตอย่างเดียว ✗ · ประกวดความสวย ✗
?? โจทย์ "ออกแบบเพื่อทดสอบประสิทธิภาพ": เลือกวิธีที่ **ทดลองใช้จริงตามสภาพที่ต้องการ** ระยะหนึ่ง แล้วนำผลมาปรับ

## เริ่มจากความต้องการของผู้ใช้
• ขั้นแรก: **ทำความเข้าใจว่าผู้ใช้เจอปัญหาอะไร ต้องการอะไร** (ศึกษากลุ่มเป้าหมาย) → รวบรวมข้อมูล → ออกแบบ → ทดสอบกับผู้ใช้
• ผิด: เอาของที่มีอยู่มาลอกโดยไม่ปรับ · ทำเทคนิคก่อนถามผู้ใช้ · ทำเร็วแล้วขออนุมัติโดยไม่ทดสอบกับผู้ใช้
[[fig:m3-ip|ทรัพย์สินทางปัญญา]]
ex: ชมรมพัฒนาแอปช่วยผู้สูงอายุในชุมชน → ขั้นแรก: สัมภาษณ์ผู้สูงอายุ/ผู้ดูแล เพื่อรู้ว่าต้องการอะไร (ตัวอักษรใหญ่ เสียงอ่าน) → แล้วออกแบบ ทดสอบกับผู้สูงอายุ · ไม่ใช่เขียนโปรแกรมก่อนแล้วค่อยถาม
ex: ต้องการใช้ภาพและเพลงของผู้อื่นในแอป → ขออนุญาตหรือใช้ผลงานที่อนุญาตให้ใช้ · อ้างอิงที่มา
?? โจทย์ให้เลือกแนวทางพัฒนาซอฟต์แวร์ที่ถูกขั้น: เลือกข้อที่ **เริ่มจากความต้องการของผู้ใช้ และทดสอบกับผู้ใช้** (ตัดข้อที่ข้ามขั้น ลอกของเดิม ไม่ทดสอบ)

• ขั้นตอน: **วิเคราะห์ปัญหา → ระบุเงื่อนไข (งบ เวลา ผลกระทบ) → เทียบทางเลือก → เลือกที่ผ่านทุกเงื่อนไข → วางแผนทีละขั้น**
• เงื่อนไขที่พบ: **งบจำกัด** · **ห้ามกระทบงานปัจจุบัน** · **แก้ที่สาเหตุ**
• วิธี **ปรับปรุงทีละขั้น** (หาจุดอ่อนหลักแล้วอัปเกรดที่คุ้ม) มักผ่านทั้งงบและไม่รบกวนงานเดิม
ex: ระบบรับออเดอร์เก่าของโรงอาหารช้า งบน้อย ห้ามปิดร้านขณะเปลี่ยน → วิเคราะห์จุดอ่อน (จดมือซ้ำ) → ปรับทีละขั้น: เริ่มจากแท็บเล็ตรับออเดอร์ 1 จุด แล้วขยาย · ไม่ซื้อระบบใหม่ทั้งหมด (เกินงบ) · ไม่ปิดร้านเปลี่ยนระบบ (กระทบ)
ex: ตารางเงื่อนไข: ทางเลือก A เกินงบ · B ไม่แก้สาเหตุ · C ผ่านทุกข้อ → เลือก C

## ระบุปัญหาและรวบรวมข้อมูล
• ระบุปัญหา → ตั้งเป้าหมาย → รวบรวมข้อมูล (สัมภาษณ์ สำรวจ ค้นคว้า)
ex: ปัญหา "น้ำในโรงเรียนไหลทิ้ง" → เก็บข้อมูลจุดที่รั่ว ปริมาณน้ำที่เสีย
@@ M3 | ว 4.1 | ม.1/4 | ทดสอบ ประเมิน และปรับปรุงแก้ไข (ยังไม่เคยออกสอบ 2561–2568)
## ทดสอบและปรับปรุง
• ทดสอบตามเกณฑ์ → ระบุข้อบกพร่อง → ปรับปรุง → ทดสอบซ้ำ → นำเสนอผล
ex: ถังเก็บน้ำฝนรั่วที่รอยต่อ → ซ่อมรอยต่อ แล้วทดสอบใหม่
@@ M3 | ว 4.1 | ม.2/1 | แนวโน้มเทคโนโลยีและผลกระทบ (ยังไม่เคยออกสอบ 2561–2568)
## เลือกใช้เทคโนโลยีและผลกระทบ
• พิจารณา **ประโยชน์ ต้นทุน ผลต่อชีวิต สังคม สิ่งแวดล้อม** ก่อนเลือกใช้
ex: เลือกหลอดไฟ LED แทนหลอดไส้ → ประหยัดไฟ อายุยาว ลดไฟฟ้า
@@ M3 | ว 4.1 | ม.2/2 | ระบุปัญหาของชุมชน (ยังไม่เคยออกสอบ 2561–2568)
## ปัญหาของชุมชน
• สำรวจชุมชน → สรุปกรอบของปัญหา (ใคร ที่ไหน เมื่อไร) → รวบรวมข้อมูล
ex: ชุมชนริมคลองน้ำเน่าช่วงฤดูแล้ง → กรอบปัญหา: น้ำนิ่ง ขยะ ปลาตาย
@@ M3 | ว 4.1 | ม.3/1 | เทคโนโลยีกับวิทยาศาสตร์และคณิตศาสตร์ (ยังไม่เคยออกสอบ 2561–2568)
## เทคโนโลยีใช้ความรู้ศาสตร์อื่น
• ใช้ความรู้วิทยาศาสตร์/คณิตศาสตร์ในการออกแบบ (ความแข็งแรงวัสดุ การคำนวณ)
ex: ออกแบบสะพานเล็ก → ใช้ความรู้แรงและคณิตศาสตร์คำนวณน้ำหนักที่รับได้
@@ M3 | ว 4.1 | ม.3/4 | ทดสอบ วิเคราะห์ข้อบกพร่องภายใต้เงื่อนไข (ยังไม่เคยออกสอบ 2561–2568)
## วิเคราะห์ข้อบกพร่อง
• วิเคราะห์ว่าทำไมไม่ผ่าน (ใช้ข้อมูลการทดสอบ) แล้วแก้ภายใต้เงื่อนไขเดิม (งบ เวลา)
ex: ที่กรองน้ำช้าเกินเป้า → ตรวจชั้นกรอง พบทรายละเอียดเกิน → ปรับขนาดทราย ทดสอบอีก
