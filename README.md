# ติว O-NET วิทยาศาสตร์ ป.6 · ม.3

เว็บแอปติวข้อสอบ O-NET วิทยาศาสตร์ แยกตามมาตรฐานและตัวชี้วัดตาม Test Blueprint ของ สทศ.
หน้าเว็บและเนื้อหา (ผังข้อสอบ ข้อสอบ สรุป เฉลย) อยู่บน GitHub Pages เป็นไฟล์ JSON · Google Apps Script + Google Sheets เก็บเฉพาะห้องเรียน นักเรียน แอดมิน และคะแนน (ดู "โครงสร้างระบบ" ท้ายหัวข้อไฟล์)

## ไฟล์
- `index.html` โครงหน้าเว็บ + ตั้งค่า `API_URL` · `app.css` หน้าตาแนวอวกาศทั้งระบบ · `js/` โค้ดหน้าเว็บ (`core.js` แกนกลาง/โหลดเนื้อหา/บันทึกคะแนน · `student.js` หน้านักเรียนและทำข้อสอบทีละข้อ · `admin.js` หน้าครู · `rich.js` ตัวแปลงสรุป/เฉลยและภาพ SVG · `boot.js` เริ่มระบบ) · `grade.js` กติกาตรวจคะแนน (ใช้ในเครื่องนักเรียน และต้องเหมือน `Code.gs` ทุกตัวอักษร ตรวจโดย `tools/test/grading.mjs`)
- `apps-script/Code.gs` ระบบหลังบ้าน (ห้อง นักเรียน แอดมิน คะแนน — ไม่เก็บเนื้อหา)
- `content/` ไฟล์เนื้อหา JSON **สร้างอัตโนมัติจาก `data/`** (`node tools/build-content.mjs` หรือ `tools/publish.mjs`) ไม่แก้มือและไม่อยู่ใน git ของโฟลเดอร์งาน แต่ขึ้นเว็บทุกครั้งที่ publish
- `images/` ภาพประกอบข้อสอบที่แคปจาก PDF ต้นฉบับ ชื่อไฟล์ `ระดับ-ปี-ข้อ.png` เช่น `P6-2568-07.png` (ต้องอัปโหลดขึ้น GitHub Pages พร้อม index.html)
- `data/blueprint.tsv` ผังข้อสอบ (Test Blueprint) ปีการศึกษา 2569 ของ ป.6 และ ม.3
- `data/questions-<ระดับ>-<ปี>.tsv` ข้อสอบพร้อมเฉลย เช่น `questions-P6-2568.tsv`
- `data/REVIEW.md` รายการที่ต้องตรวจทานของข้อมูลชุดนี้ (รวมหัวข้อ "สรุปเนื้อหา")
- `data/SUMMARY.md` สรุปรวมข้อสอบ 2561–2568 (สร้างด้วย `node tools/summary.mjs`)
- `data/summaries/` สรุปเนื้อหารายมาตรฐาน หนึ่งไฟล์ต่อมาตรฐานต่อระดับ เช่น `P6-2.1.txt` (ป.6 ว 2.1) `M3-2.3.txt` (ม.3 ว 2.3) และตารางตรวจความครอบคลุมรายข้อ `coverage-*.tsv` / `COVERAGE-*.md`
- `figs/P6.js` `figs/M3.js` ภาพ SVG ประกอบสรุป (แยกตามระดับ เด็ดขาด) **ต้องอัปโหลดขึ้น GitHub Pages พร้อม index.html**
- `source/` ไฟล์ PDF ต้นฉบับจาก สทศ. (`Blueprint-P6-2569.pdf`, `Blueprint-M3-2569.pdf`, `P6-<ปี>.pdf`, `M3-<ปี>.pdf`)

## ติดตั้ง (ประมาณ 10 นาที)
1. สร้าง Google Sheet ใหม่ → ส่วนขยาย → Apps Script → วางโค้ดจาก `apps-script/Code.gs`
2. เลือกฟังก์ชัน `setup` แล้วกด Run หนึ่งครั้ง → เปิด "บันทึกการดำเนินการ" จดรหัสผ่านของผู้ใช้ `admin` (แสดงครั้งเดียว)
3. Deploy → New deployment → Web app → Execute as: **Me**, Who has access: **Anyone** → คัดลอก URL ที่ลงท้ายด้วย `/exec` (ครั้งแรกจะขอสิทธิ์ "เชื่อมต่อบริการภายนอก" เพราะ Apps Script ต้องโหลดไฟล์เฉลยจากเว็บเพื่อตรวจคะแนนซ้ำ — กดอนุญาต)
4. เปิด `index.html` ใส่ URL นั้นในบรรทัด `const API_URL = '';`
5. อัปโหลดขึ้น GitHub แล้วเปิด Settings → Pages → Deploy from branch (main, root) · หลังจากนี้ขึ้นเว็บด้วย `node tools/publish.mjs` (สร้าง `content/` ให้เองทุกครั้ง)

แก้ `Code.gs` ทุกครั้งต้อง Deploy → Manage deployments → แก้ไข → New version

## ใช้งาน
- **ผู้ดูแลกลาง**: เพิ่มโรงเรียน → สร้างแอดมินโรงเรียน (เนื้อหาข้อสอบไม่ต้องนำเข้า โหลดจาก `content/` อัตโนมัติ)
- **แอดมินโรงเรียน**: เพิ่มรายชื่อนักเรียน (ห้อง,เลขที่,ชื่อ) ดูรายงานผล เพิ่มแอดมินในโรงเรียนตัวเอง
- **นักเรียน**: กรอก **รหัสห้องเรียน** 6 ตัว (ครูดูได้ที่แท็บ "นักเรียน" ในหน้าแอดมิน) แล้วเลือกชื่อตัวเอง → ฝึกรายมาตรฐาน/ตัวชี้วัด หรือทำข้อสอบจำลองตามผัง

- ข้อสอบ: `data/questions-<ระดับ>-<ปี>.tsv` · สรุป: `data/summaries/` · เฉลยละเอียด: `data/solutions/`

## โครงสร้างระบบ: เนื้อหา JSON + Apps Script
| ส่วน | อยู่ที่ไหน | โหลดเมื่อ |
|---|---|---|
| ผัง มาตรฐาน ตัวชี้วัด จำนวนข้อ รายการข้อของโหมดฝึก/จำลอง | `content/<ระดับ>/meta.json` | เปิดหน้าแรกนักเรียน |
| โจทย์รายปี | `content/<ระดับ>/q-<ปี>.json` | เปิดข้อสอบ/ฝึก (เฉพาะปีที่ต้องใช้) |
| กุญแจเฉลย + คำอธิบายสั้น | `content/<ระดับ>/k-<ปี>.json` | ตอนทำข้อสอบ (ตรวจในเครื่อง) · Apps Script โหลดเองเพื่อตรวจซ้ำ |
| เฉลยละเอียด | `content/<ระดับ>/s-<ปี>.json` | หลังส่งคำตอบ (ใส่ลงหน้าผลลัพธ์ทีหลัง) |
| สรุปเนื้อหา | `content/<ระดับ>/sum-<มาตรฐาน>.json` | เปิดหน้าสรุป |
| รายการไฟล์ + ฉบับ | `content/manifest.json` | ทุกครั้งที่เปิดเว็บ (ตรวจฉบับใหม่) · ไฟล์อื่นเรียกด้วย `?v=<hash>` เปลี่ยนเนื้อหา = เบราว์เซอร์ดึงใหม่ทันที |
| ห้อง นักเรียน แอดมิน คะแนน | Google Sheets ผ่าน Apps Script | `enter` (กรอกรหัสห้อง ได้รายชื่อในคำขอเดียว) · `progress` (ความคืบหน้า โหลดเบื้องหลัง) · `submitAttempt` (บันทึกคะแนน) |

**การตรวจคะแนน**: เครื่องนักเรียนตรวจเองทันที (โหมดฝึก/ข้อสอบรายปี/จำลอง) แล้วส่งคำตอบไป Apps Script เบื้องหลัง · Apps Script ตรวจซ้ำจากกุญแจเฉลยเอง **แล้วบันทึกค่าที่ตัวเองตรวจได้** (ไม่เชื่อคะแนนจากเครื่องนักเรียน) ถ้าต่างจากที่แสดง หน้าผลลัพธ์แจ้งว่าระบบตรวจซ้ำได้เท่าไร · ส่งไม่สำเร็จ (เน็ตหลุด) คำตอบเก็บในเครื่องและส่งใหม่อัตโนมัติ · แต่ละครั้งมี `attemptId` ส่งซ้ำไม่บันทึกซ้ำ

## โหมดสอบของครู (โครงที่เตรียมไว้ — ยังไม่มีหน้าจอ)
เป้าหมาย: ครูกำหนดการสอบที่ **เฉลยไม่ถูกส่งไปเครื่องนักเรียน** (ไม่ดาวน์โหลดไฟล์ `k-*.json`) ตรวจและบันทึกที่ Apps Script ทั้งหมด
โครงที่มีอยู่แล้ว (ไม่ต้องรื้อ ต่อยอดได้):
1. **แยกไฟล์เฉลยออกจากโจทย์** `q-*.json` ไม่มีคำตอบ · `k-*.json` มีคำตอบ → โหมดปกติโหลด `k-*.json` ตรวจในเครื่อง ส่วนโหมดสอบของครูไม่โหลด
2. **หน้าเว็บ**: `quiz(mode, std, ind, skip, secure)` ส่ง `secure = true` → ไม่โหลด `k-`/`s-` · `submit()` เรียก `submitAttempt` พร้อม `secure: true` ได้ผลกลับเฉพาะถูก/ผิด คะแนน (ไม่มีเฉลย ไม่มีเฉลยละเอียด) · ทดสอบแล้วด้วย `tools/test/secure.mjs`
3. **Apps Script**: `submitAttempt` รองรับ `secure`/`reveal` · `loadKeys()` ใช้แท็บ `Keys` ในชีต (`level | year | itemNo | type | answer | standard`) ก่อนไฟล์สาธารณะ → ข้อสอบที่เฉลย **ห้ามอยู่ใน repo สาธารณะ** ให้เก็บเฉลยไว้ในแท็บ `Keys` เท่านั้น (ไม่ใส่ใน `data/` และไม่ให้ `build-content.mjs` สร้าง `k-*.json`)
สิ่งที่ต้องเพิ่มเมื่อจะทำจริง: (ก) แท็บ `Exams` ในชีต (รหัสการสอบ ห้อง/โรงเรียน เวลาเปิด-ปิด รายการข้อ) + action `startExam`/`getExam` ที่ส่งโจทย์ให้เฉพาะเมื่ออยู่ในเวลาสอบ (โจทย์ที่ยังไม่เปิดสอบก็ไม่ควรอยู่ใน repo สาธารณะ → เก็บแท็บ `ExamItems` แทนไฟล์ `q-*.json`) (ข) หน้าจอครูสร้าง/ปิดการสอบ และหน้านักเรียนเข้าสอบ (ค) จำกัดจำนวนครั้ง/จับเวลาฝั่งเซิร์ฟเวอร์ (ง) retry เมื่อส่งไม่สำเร็จ (โหมด secure ต้องไม่หายคำตอบ: เก็บคำตอบใน localStorage แล้วส่งซ้ำด้วย `attemptId` เดิม ซึ่งเซิร์ฟเวอร์รับซ้ำได้อยู่แล้ว)
ข้อควรระวัง: ข้อสอบ O-NET ปีเก่าในโหมดฝึกเปิดเฉลยอยู่ใน repo สาธารณะแล้ว จึงเปิดให้ตรวจในเครื่องได้ · โหมดสอบของครูใช้กับข้อสอบที่ครูแต่งเองเท่านั้น

### รูปแบบไฟล์ข้อสอบ (11 คอลัมน์ ไม่มีหัวตาราง ห้ามมี tab หรือขึ้นบรรทัดใหม่ในเซลล์)
`level | ปีการศึกษา | ข้อที่ | มาตรฐาน | ตัวชี้วัด | โจทย์ | ลิงก์รูป | ตัวเลือก | เฉลย | คำอธิบาย | type`

| type | ความหมาย | คอลัมน์ตัวเลือก | เฉลย |
|---|---|---|---|
| `mc` | ปรนัย 4 ตัวเลือก | ตัวเลือกคั่นด้วย `\|\|` · **เว้นว่าง** ถ้าตัวเลือกอยู่ในภาพ (หน้าเว็บแสดงปุ่ม 1–4) | เลขตัวเลือก เช่น `3` |
| `complex` | เลือกตอบเชิงซ้อน ใช่/ไม่ใช่ | ข้อความย่อยคั่นด้วย `\|\|` (แสดงทีละบรรทัดพร้อมปุ่ม ใช่/ไม่ใช่) | เรียงตามข้อย่อย เช่น `ใช่,ใช่,ไม่ใช่` |
| `order` | เรียงลำดับ | รายการให้เลือกคั่นด้วย `\|\|` (ลำดับในรายการ = หมายเลข 1, 2, 3…) | หมายเลขตามลำดับ เช่น `5,6,4` (จำนวนช่องที่ให้เลือก = จำนวนตัวในเฉลย) |
| `fill` | เติมคำตอบ | เว้นว่าง | คำตอบที่ต้องพิมพ์ให้ตรง |

- **เฉลยหลายคำตอบ** (กระดาษเฉลยของ สทศ. ระบายสองช่องในข้อเดียวกัน): คั่นด้วย `|` ภายในช่องเดียว ระบบนับถูกทั้งสองคำตอบ ไม่เลือกให้เอง · ปรนัย `1|2` · เชิงซ้อนคั่นเป็นรายข้อย่อยด้วย `,` เช่น `ใช่,ใช่|ไม่ใช่,ไม่ใช่` (ข้อย่อยที่ 2 รับได้ทั้ง ใช่ และ ไม่ใช่) · หน้าเฉลยแสดง "1 หรือ 2" · ปัจจุบันมี M3-2561 ข้อ 26 และ P6-2561 ข้อ 31.2 · ทดสอบตรรกะด้วย `node tools/test/alts.mjs`
- ถ้าไม่ใส่ `type` ระบบถือเป็น `mc` เมื่อมีตัวเลือก และ `fill` เมื่อตัวเลือกว่าง (ไฟล์ 10 คอลัมน์แบบเดิมจึงยังนำเข้าได้)
- **ลิงก์รูป**: ใส่ชื่อไฟล์ (เช่น `P6-2568-07.png`) ระบบจะแสดงจากโฟลเดอร์ `images/` ของเว็บ หรือใส่ลิงก์ `https://…` ก็ได้ ภาพแสดงทั้งหน้าทำข้อสอบ หน้าเฉลย และตอนพิมพ์ PDF
- **ขีดเส้นใต้**: ครอบข้อความด้วย `__…__` ในโจทย์ ตัวเลือก หรือคำอธิบาย เช่น `ข้อใด__ไม่__ถูกต้อง`
- **มาตรฐาน/ตัวชี้วัด**: รูปแบบ `ว 2.3` และ `ป.6/1` หรือ `ม.3/2` ตามหลักสูตรฯ ฉบับปรับปรุง 2560

## สรุปเนื้อหา (ไฟล์ `data/summaries/`)
สรุปเก็บเป็นไฟล์ข้อความ หนึ่งไฟล์ต่อ **ระดับ + มาตรฐาน** ตั้งชื่อ `<ระดับ>-<มาตรฐาน>.txt` เช่น `P6-2.1.txt` · ป.6 กับ ม.3 แยกไฟล์ แยกภาพ ไม่ใช้เนื้อหาร่วมกัน
**โครงสร้างไฟล์**: บรรทัดที่ขึ้นต้น `//` ก่อนหัวข้อแรกเป็นหมายเหตุ · แต่ละตัวชี้วัดขึ้นต้นด้วยบรรทัดหัวข้อ `@@ ระดับ | มาตรฐาน | ตัวชี้วัด | ชื่อหัวข้อ` ตามด้วยเนื้อหา · เรียงตัวชี้วัดจากที่ข้อสอบ 2561–2568 ออกบ่อยสุด ตัวที่ไม่เคยออกอยู่ท้ายไฟล์และสั้นกว่า · หน้าเว็บแสดงตามลำดับในไฟล์ (หนึ่งมาตรฐาน = หนึ่งหน้า กด "สรุป + ฝึก" ที่มาตรฐาน)
**ขึ้นเว็บ**: แก้ไฟล์ `data/summaries/<ไฟล์>.txt` แล้วรัน `node tools/publish.mjs` (ไม่ต้องนำเข้า) · ตรวจรูปแบบได้ด้วย `node tools/summaries.mjs`
**markup ในเนื้อหา** (ต้นบรรทัด):
| ต้นบรรทัด | ผล |
|---|---|
| `## หัวข้อ` | หัวข้อย่อย |
| `• รายการ` | รายการ |
| `!! ข้อความ` | กล่อง "จำให้แม่น" (บรรทัด `!!` ติดกันรวมเป็นกล่องเดียว) |
| `?? ข้อความ` | กล่อง "ข้อสอบชอบถาม" (ต้องมาจากรูปแบบคำถามที่ออกจริงและจุดที่นักเรียนมักพลาด) |
| `ex: ข้อความ` | กล่อง "ตัวอย่าง" (บรรทัด `ex:` ติดกันรวมเป็นกล่องเดียว เว้นบรรทัดว่างเมื่อต้องการแยกเป็นอีกกล่อง) |
| `= สมการ  สมการ` | สมการกึ่งกลาง คั่นหลายสมการด้วยช่องว่างตั้งแต่ 2 ช่องขึ้นไป |
| `{เศษ/ส่วน}` | เศษส่วนในบรรทัดใดก็ได้ เช่น `I = {V/R}` (ห้ามมี / ซ้อนในเศษหรือส่วน) · `**คำ**` ตัวหนา |
| `| ก | ข |` | ตาราง (แถวแรกเป็นหัวตาราง) |
| `[[fig:ชื่อ|คำบรรยาย]]` | ภาพ SVG ชื่อที่นิยามในไฟล์ `figs/<ระดับ>.js` (ไม่ใช้ภาพแคปข้อสอบ) |
- ตัวอย่างในสรุปต้อง **เขียนใหม่** (ตัวเลข สิ่งของ สถานการณ์ไม่ซ้ำโจทย์) ใช้วิธีคิดแบบเดียวกับข้อสอบ
- การเพิ่มภาพ: เพิ่ม `F['ชื่อ'] = svg(...)` ใน `figs/P6.js` หรือ `figs/M3.js` แล้วอ้างด้วย `[[fig:ชื่อ|...]]` · ตัวเลขทุกตัวในภาพต้องถูกตามหลักวิชา (ตำแหน่ง F, C ทิศลูกศร ป้ายกำกับ)
- **ตรวจไฟล์สรุป**: `node tools/summaries.mjs` (รูปแบบ markup, ภาพมีจริง, ตัวชี้วัดครบตาม Blueprint 2569, เรียงตามจำนวนข้อ, ไม่คัดลอกโจทย์, ไม่ปนศัพท์ของอีกระดับ) · `node tools/coverage.mjs P6-2.1 M3-2.3` (ตรวจตารางครอบคลุมรายข้อและสร้าง PDF) · `node tools/test/summary-shots.mjs P6 "ว 2.1"` (เปิด server ค้างไว้: ภาพหน้าจอมือถือ ตรวจป้ายใน SVG ทับกัน และพิมพ์ PDF)
- **PDF**: ปุ่ม "ดาวน์โหลดสรุป PDF" ตั้งกฎพิมพ์ให้กล่อง ตาราง สมการ และภาพไม่ถูกตัดข้ามหน้า
- ข้อสอบนอกหลักสูตรปัจจุบันไม่นับในตารางสรุปตาม Blueprint (ดูหัวข้อโหมดข้อสอบ)
